# ניתוח ארכיטקטורה: "תוסף על גוגל מפות" — האם והאם חינמי

> מסמך עבודה. נכתב 2026-06-06. לחזרה משותפת מחר.
> שאלת המשתמש: להפוך את PlanMyTrip לשכבה מעל חשבון גוגל מפות האישי —
> שחשבון הגוגל יהיה הבסיס, וכל הפונקציות שבנינו יעבדו סביבו. הכל חינמי ככל הניתן.

## חלק 1 — ריקפ: מה התוכנה עושה היום

**PlanMyTrip / GONISWORLD — מתכנן טיולים, React בקובץ index.html יחיד.**

פונקציות קיימות:
1. **ניהול טיולים** — כמה טיולים, יצירה/שינוי-שם/מחיקה, טיול פעיל.
2. **מפה** (Google Maps JS API) — סמנים, מסלולי יום, לחיצה על POI → חלון פרטים, תיבת חיפוש.
3. **בנק אטרקציות** — אוסף מקומות, קיבוץ לפי מדינה, תיוג מקור (liked/wantToGo/saved/list/itinerary), חיפוש, מיון, מחיקה קבוצתית.
4. **ייבוא מגוגל**:
   - רשימה משותפת (`entitylist/getlist`) → שם + קואורדינטות + Feature ID.
   - מקום בודד מקישור.
   - Google Takeout (JSON/CSV).
5. **העשרת פרטים** — דרך `/maps/preview/place` החינמי: כתובת, דירוג, שעות, אתר, טלפון, סוג, מדינה. (מאז v209-v211)
6. **ציר זמן / ימים** — בלוקים (פעילויות), מוצא/יעד, שעות, זמני נסיעה בין בלוקים.
7. **תכנון יום** — הוספת מקומות לימים, התחלה/סיום, בנק-יום.
8. **הוצאות** — קטגוריות, סכומים, גרף.
9. **מסמכים, הערות, קישורים** — לכל טיול.
10. **מזג אוויר** — לפי עיר.
11. **רשימות אריזה / צ'קליסט** — לפי קטגוריות.
12. **סנכרון** — Firebase (בין מכשירים) + GitHub Token (ל-Actions ולאחסון).
13. **שמות מותאמים, הערות למקום, ניהול מקור רשימה.**
14. **תצוגת סיכום / overview.**

**ערוצי גישה לגוגל שכבר בשימוש (כולם חינמיים חוץ ממפה+Places):**
- `entitylist/getlist` — רשימות משותפות (פנימי, חינם, דרך פרוקסי/Action).
- `/maps/preview/place` — פרטי מקום מלאים (פנימי, חינם, דרך פרוקסי/Action).
- Google Takeout — ייבוא ידני (רשמי, חינם).
- Places API + Maps JS — **בתשלום** (טעינת מפה, לחיצה על POI, חיפוש, כפתורי 🔍).

## חלק 2 — השאלה המרכזית: האם אפשר שחשבון הגוגל יהיה הבסיס?

### התשובה הקצרה
**לא במלואו, וזו מגבלה של גוגל — לא שלנו.** גוגל **לא** חושפת שום API ציבורי לקריאה/כתיבה של הנתונים האישיים בחשבון מפות:
- רשימות שמורות (Saved / Want to go / Favorites / Labeled places)
- היסטוריית מיקום / Timeline
- מקומות מסומנים בכוכב

אין scope ב-OAuth ("התחבר עם גוגל") שמעניק גישה לדברים האלה. ה-"Google Maps APIs" כולם שייכים ל-Maps **Platform** (נתוני מקומות ציבוריים), בעוד ה-Saved/Timeline שייכים למוצר הצרכני וסגורים לחלוטין לצד שלישי.

### למה לא
| מה רצינו | האם אפשר? | למה |
|----------|:---------:|-----|
| OAuth → לקרוא את הרשימות השמורות שלי | ❌ | אין scope כזה בגוגל |
| לקרוא Timeline / היסטוריית מיקום | ❌ | אין API ציבורי; גוגל העבירה ל-on-device |
| לכתוב מקום ל-"שמור" שלי דרך API | ❌ | אין API |
| לגשת לרשימה פרטית (לא משותפת) חי | ❌ | דורש את עוגיות ההתחברות של גוגל — חסום cross-origin |
| תוסף *בתוך* אפליקציית גוגל מפות | ❌ | לגוגל מפות אין פלטפורמת תוספים (בניגוד ל-Workspace) |

### מה כן אפשר (הערוצים החוקיים/חינמיים היחידים)
| ערוץ | סוג | חי? | עלות |
|------|-----|:---:|:----:|
| רשימה **משותפת** (entitylist) | קריאה | חצי-חי (re-sync ידני) | חינם |
| **Takeout** (כל החשבון) | קריאה | ידני, תקופתי | חינם |
| `/maps/preview/place` | העשרה | לפי דרישה | חינם |
| **My Maps** (KML, אם המשתמש משתמש בזה) | קריאה | חצי-חי | חינם |
| **Deep links** לגוגל מפות | הפנייה | חי | חינם |
| **Calendar/Drive OAuth** | כתיבה לחשבון | חי | חינם (מכסה) |

> מסקנה: **כבר היום אנחנו משתמשים בכמעט כל הערוצים החינמיים הקיימים.** התחושה של "ניתוק" היא מובנית בעיצוב של גוגל, לא פער שאפשר לסגור בארכיטקטורה חכמה. הדבר הקרוב ביותר ל-"חשבון גוגל כבסיס" הוא: רשימות משותפות + Takeout כמקור, ו-deep-links + Calendar/Drive כיעד.

## חלק 3 — הארכיטקטורה המומלצת: "Hub" סביב גוגל (לא backend חי)

האפליקציה נשארת ה-system of record (Firebase/local), אבל הופכת ל**מרכז שקורא מגוגל ומעביר בחזרה לגוגל**:

### A. READ (משיכה מגוגל — חינם)
1. **"רשימה מחוברת" / one-click re-sync** — כפתור שמרענן רשימה משותפת ומושך מקומות חדשים (dedup). מרגיש כמו רשימה מסונכרנת. רוב הקוד כבר קיים.
2. **Takeout משופר** — אשף שמסביר בדיוק איך לייצא ולמשוך הכל (המקור הרשמי המלא היחיד).
3. **My Maps (אופציונלי)** — אם המשתמש שם מקומות ב-My Maps, יש KML/network-link נגיש. ערוץ חצי-חי לגיטימי.
4. **העשרה עשירה יותר** — תגובת `/maps/preview/place` מכילה ~260 שדות (d6). היום מנצלים ~8. אפשר להוסיף **בחינם**: תמונות, שעות שבוע מלא, "שעות עומס" (popular times), רמת מחיר, נגישות, "אנשים גם חיפשו", קטעי ביקורות. סוגר את פער ה-"עושר" בלי עלות.

### B. HAND-OFF (העברה לחשבון הגוגל של המשתמש — חינם)
5. **Deep links בכל מקום** — כל מקום/יום/מסלול עם קישור שנפתח באפליקציית גוגל מפות שבה המשתמש **מחובר** → שם הוא יכול לשמור, לנווט, לראות ביקורות בחשבון שלו. גשר לחשבון בלי API.
6. **Navigation handoff** — "נווט את היום הזה" → קישור Google Maps directions עם waypoints (חינם, ללא API).
7. **Save-to-Google** — אי אפשר לכתוב לרשימות דרך API, אבל deep-link למקום מאפשר ללחוץ "שמור" באפליקציה שלו.
8. **Calendar API (OAuth, חינמי-במכסה)** — לדחוף את ה-itinerary ליומן גוגל של המשתמש. **אינטגרציית חשבון אמיתית, רשמית.**
9. **Drive/Photos API (OAuth)** — לאחסן מסמכי/תמונות טיול ב-Drive שלו.

### C. הורדת עלויות (להגיע ל-~100% חינם)
10. **המרת לחיצת-מפה + חיפוש ל-`/maps/preview/place`** (כבר ניתחנו — ChIJ→FID עובד בפיענוח טהור).
11. **החלפת תצוגת המפה עצמה** מ-Google Maps JS ל-**Leaflet + OSM/MapTiler (free tier)** — מבטל את עלות ה-Maps Platform היחידה שנותרת. מאבדים את שכבת ה-POI הלחיצה של גוגל, אבל את הנתונים אנחנו כבר מקבלים מה-endpoint החינמי. **שינוי ארכיטקטוני משמעותי — ההחלטה הכי משפיעה על עלות.**
12. **Routing/Geocoding חינמי** — OSRM/Valhalla + Nominatim במקום Routes/Geocoding API.

## חלק 4 — אמינות וסיכונים (חובה לדבר על זה מחר)

1. **Endpoints פנימיים לא-רשמיים** (entitylist, preview/place) — גוגל יכולה לשנות/לשבור בכל רגע. כבר שבריר. בנייה של עוד מעליהם = יותר חשיפה. **מיטיגציה:** להשאיר Takeout כ-fallback רשמי.
2. **פרוקסים ציבוריים לא אמינים** (כבר נתקלת בכשלים). **המלצה חזקה:** פרוקסי קטן משלנו על **Cloudflare Worker (free tier — 100K בקשות/יום חינם)**. הרבה יותר אמין מפרוקסי ציבורי, ופותר CORS לכל הקריאות החינמיות. זה כנראה השדרוג הכי משתלם.
3. **ToS** — גרידה של endpoints פנימיים עלולה לנגוד בתנאי השימוש של גוגל. לשימוש אישי הסיכון נמוך, אבל חשוב לומר בכנות.
4. **CORS** — אומת: ל-`/maps/preview/place` אין כותרות CORS → כל קריאה מהדפדפן חייבת פרוקסי (Worker פותר).

## חלק 5 — סיכום והמלצה

**מה אפשרי (חינם, מומלץ, לפי סדר ערך/מאמץ):**
1. פרוקסי Cloudflare Worker — אמינות לכל הקריאות החינמיות. (תשתית)
2. העשרה עשירה יותר מ-preview/place (תמונות, popular times, ביקורות) — סוגר פער עושר, חינם.
3. המרת לחיצת-מפה + חיפוש לנתיב חינמי — חוסך Places.
4. Deep-links + Navigation handoff — "מרגיש מחובר" לחשבון.
5. one-click re-sync לרשימה משותפת — תחושת רשימה מסונכרנת.
6. Calendar/Drive OAuth — אינטגרציית חשבון אמיתית ורשמית.
7. (גדול) החלפת מפה ל-Leaflet/OSM — מבטל את עלות המפה לגמרי.

**מה לא אפשרי (מגבלת גוגל, לא שלנו):**
- חשבון מפות אישי כ-backend חי (רשימות שמורות/Timeline). אין API. Takeout הוא הערוץ המלא היחיד והוא ידני.

**שורה תחתונה:** אפשר להפוך את האפליקציה ל-"hub" שמרגיש מחובר מאוד לגוגל ושהוא כמעט לגמרי חינמי — אבל לא ל-backend חי של החשבון האישי. הצעד הראשון הכי חכם: פרוקסי Worker + העשרה עשירה יותר. הצעד הכי גדול לחיסכון: החלפת תצוגת המפה.

## חלק 6 — תוכנית הביצוע (אושר ע"י המשתמש)

**הוחלט:** אופציה 1 (קובץ מקביל `index-v2.html`) עם **כל** ההמלצות.
**דרישה מיוחדת:** אינטגרציית Calendar — **לכל טיול כתובת יומן נפרדת** (כל טיול עשוי
להיות אדם אחר עם יומן אחר). שדה `calendarId` ברמת הטיול + בורר יומן בהגדרות הטיול.

### בוצע ✅
- `index-v2.html` נוצר כעותק מדויק.
- בידוד נתונים מלא: `localStorage` → מפתח `caravanCtrl_he_v2` (seed חד-פעמי מהישן, קריאה בלבד).
- בידוד ענן: Firebase node → `/planmytrip_v2/` (לא נוגע בנתוני הגרסה הישנה).
- תווית גרסה: `v2.0 🧪`.
- tag שחזור: `stable-v212`.

### סדר בנייה
| # | משימה | קוד בלבד? | דורש פעולה שלך |
|---|-------|:---------:|----------------|
| 1 | פרוקסי Cloudflare Worker | אני כותב | **כן** — הרשמה חינם + deploy + לתת לי URL |
| 2 | העשרה עשירה (תמונות, popular times, מחיר, ביקורות) | ✅ | לא |
| 3 | המרת לחיצת-מפה + חיפוש לנתיב חינמי | ✅ | (תלוי בפרוקסי #1 לאמינות) |
| 4 | Deep-links + Navigation handoff | ✅ | לא |
| 5 | Re-sync רשימה בלחיצה | ✅ | לא |
| 6 | Google Calendar — יומן לכל טיול | חלקי | **כן** — OAuth Client ID ב-Google Cloud |
| 7 | החלפת מפה ל-Leaflet/OSM | ✅ | החלטה: לאשר/לא |

### שני דברים שדורשים הקמה שלך (אפשר במקביל לבנייה)
- **Cloudflare Worker** (להצעה 1): הרשמה חינם ל-cloudflare.com → צור Worker → אדביק קוד → תן לי את ה-URL.
- **Google OAuth Client** (להצעה 6): ב-Google Cloud Console → Credentials → OAuth client ID (Web) → להוסיף את כתובת ה-Pages כ-origin מורשה → לתת לי את ה-Client ID.
